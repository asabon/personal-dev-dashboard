# UI / UX 設計案 (UI Design)

## 1. デザインコンセプト

- **Developer First & Dark Mode**: 開発者が常時サブモニターや片隅に表示しておきたくなる、洗練されたモダンなダークテーマUI。
- **Glanceable (一目でわかる視認性)**: 数秒見るだけで「Actions無料枠の残量」「今動いているCI」「落ちているPR」を瞬時に認知できる情報レイアウト。
- **Zero Configuration Friction**: トークン入力とリポジトリ追加が直感的に行えるオンボーディング体験。

## 3. コンポーネント構成

### 3.1 ヘッダー (`Header`) & `GitHub` セクション見出し
- **ヘッダー (`Header`)**:
  - アプリケーションタイトル (`Personal Dev Dashboard`)
  - 最終更新時刻・表示モード切替トグル（詳細 / 簡易）・手動リフレッシュボタン・設定モーダル起動ボタン（⚙️）
  - ※バージョン表記はフッターに集約し、ヘッダーをスリム化
- **`GitHub` セクション見出し**:
  - セクションタイトル (`GitHub`)、接続中アカウント表示 (`Logged in as @username`)、監視リポジトリ数バッジ (`N repos`)、GitHub API レート制限残数バッジ (`API残数: 4892 / 5000`)

### 3.2 Actions 使用量カード (`ActionsUsageCard`)
- **カードタイトル**: `Actions Usage`
- **当月の使用量 (換算目安)（Primary）**: 枠の総分数（2,000 分）に対する当月消費換算分数（Ubuntu x1, macOS x10, Windows x2 を適用）と使用率
- **残り無料枠 (目安)（Secondary）**: 残り換算分数と残枠割合
- **ステータスバッジ**: 選択中アカウントの暦日ペースと消費量に基づくステータス（順調 / やや速い / ハイペース / 残り僅か）
- **仕様説明ツールチップ**: パブリックリポジトリでの実行も合算される GitHub API (Usage Summary) の仕様および OS 倍率適用について解説する Info アイコン
- **プログレスバー**:
  - 左（0分）から右（2,000分）へ伸びる消費量メーター
  - 当月の暦日進捗に基づく「本日目安」ラインマーカー
  - 単位を「分」に統一
- **OS ごとの使用量 breakdown**: Ubuntu (x1) / macOS (x10) / Windows (x2) の実稼働時間（分数）
- **個人・Organization 常時並列表示**: 個人アカウントと監視対象 Organization を並べて表示

### 3.3 Actions 稼働ステータスカード (`ActionsStatusCard`)
- **カードタイトル**: `Actions Status`
- 監視対象リポジトリすべての直近ワークフロー実行履歴（`push`, `release`, `pull_request`, `schedule`, `workflow_dispatch` 等）を横断監視。
- 同一ワークフローの最新実行状態のみを評価し、**「現在実行中（Running）」または「最新実行が失敗（Failed）のまま未解決」のワークフローのみ**を抽出表示（再実行や後続コミット・新タグで成功した場合は自動的に消去）。
- すべて正常完了している場合はヘッダーに `All Passed` バッジを表示。

### 3.4 Open PRs カード (`RepositoriesCard` & `RepoCard`)
- **カードタイトル**: `Open PRs`
- 監視中リポジトリのうち、**Open な Pull Request が存在するリポジトリ（または取得エラーがあるリポジトリ）のみ**を表示し、Open PR が 0 件のリポジトリは非表示化。
- 各リポジトリのステータスバッジ（PR数、全体のCI健全性）。

### 3.5 PR アイテムカード (`PullRequestCard`)
- PR 番号、タイトル（GitHub 公式への直接リンク）、作成者、更新日時
- ブランチ名と最新コミットの短縮 SHA
- **CI ステータス統合バッジ**:
  - ✅ **All checks passed**
  - ❌ **Checks failed** (クリックで失敗したジョブのログ URL へ)
  - ⏳ **Checks in progress**
- 個別チェックの詳細展開ポップオーバー / バッジリスト

### 3.6 設定モーダル (`SettingsModal`)
- **GitHub PAT 入力フォーム**:
  - 現在設定されているトークンのマスク表示
  - トークン更新 / 削除（ログアウト）ボタン
  - 「必要な権限付きトークンを生成する」GitHub公式へのディープリンク
- **監視リポジトリ管理**:
  - `owner/repo` 入力で追加
  - ドラッグ&ドロップまたは削除ボタン
- **更新間隔設定**: 30秒 / 60秒 / 5分 / 手動のみ

### 3.7 オンボーディング画面 (`WelcomeScreen`)
- トークンが `localStorage` に未設定の場合に自動表示される初期画面。
- なぜ安全なのか（BYOK・localStorage 保存）の説明。
- トークン作成のガイドと入力欄。

### 3.8 デバッグコントロールバー (`DebugBar`)
- URL に `?debug=true` が付与されている場合のみヘッダー直下に表示される開発・UI検証用ツールバー。
- **一括プリセット切替**: Healthy（健全）、Warning（警告）、Critical（障害・上限到達）、Empty（空状態）、Error（APIエラー）をワンクリックでダッシュボード全体に適用。
- **カード個別シミュレーション**: Actions Usage、Self-hosted Runners、Actions Status、Open PRs (Repositories)、Rate Limit をカード単位で独立して任意のシナリオ（0%、85%、100%、一部オフライン、全台停止、CI失敗混在など）に切り替え可能。
- **折りたたみトグル**: カード個別設定パネルを折りたたんで、ダッシュボード全体のレイアウト確認に集中可能。
- **Feature Module 連携**: 各 feature module の `debugScenarios` 定義を動的に読み取ってセレクタを自動構成。

## 4. バッジ表示仕様一覧

各カードおよび階層におけるステータスバッジの全パターン定義です。
色凡例: 🟢 **緑 (Emerald)** = 正常・完了 / 🟡 **黄 (Amber)** = 進行中・一部警告 / 🔴 **赤 (Rose)** = 失敗・エラー・枯渇 / 🔵 **水色 (Sky)** = 稼働中 / ⚪ **灰 (Slate)** = 0件・対象なし

### 4.1 最上部 `状況サマリー` バー (`DashboardSummaryBar`)

問題や進行中ジョブがある場合は該当カードへスクロールするボタンバッジを並記し、何もない場合のみ `異常なし` を表示します。

| 条件 | 左端ドット色 | 表示されるバッジ | 色 |
| :--- | :---: | :--- | :---: |
| 全カード正常・実行中も 0 件 | 🟢 緑 | `✓ 異常なし` | 🟢 緑 |
| Open PR に CI 失敗あり | 🔴 赤 | `✕ CI 失敗: X件 ↓` | 🔴 赤 |
| Open PR に CI 実行中あり | 🟡 黄 (失敗時は🔴) | `⟳ CI 実行中: X件 ↓` | 🟡 黄 |
| Actions Status に未解決の失敗 Run あり | 🔴 赤 | `✕ Actions 失敗: X件 ↓` | 🔴 赤 |
| Actions Status に実行中 Run あり | 🟡 黄 (失敗時は🔴) | `⟳ Actions 実行中: X件 ↓` | 🟡 黄 |
| Actions Status に取得エラー / 一部未取得あり | 🟡 黄 (失敗時は🔴) | `! Actions 取得不可 ↓` | 🟡 黄 |
| Actions Usage で使用率 95% 以上のアカウントあり | 🔴 赤 | `⚠ Actions 残X% (account) ↓` | 🔴 赤 |
| Actions Usage で使用率 85%〜94% のアカウントあり | 🟡 黄 | `! Actions 残X% (account) ↓` | 🟡 黄 |
| Self-hosted Runners に Offline ランナーあり | 🔴 赤 | `! Runner 停止: X台 ↓` | 🔴 赤 |

### 4.2 `Open PRs` カード群（3階層）

全階層共通で **「分数表示 (`1/2`) は使わず、状態ごとに 1 件以上のものを個数表示（色が状態と 1 対 1 で固定）し、全件成功時のみ `All Passed` とする」** ルールに統一しています。

#### (1) 最上位階層：`Open PRs` 親カードヘッダー (`RepositoriesCard`)
- **タイトル横件数バッジ**: `{totalPrs}件`（⚪ 灰）
- **右側サマリーバッジ**: 条件に応じて **左から順に並記** されます（初回ロード中 `isLoading=true` の間は Running / Failed / Passed / 0 PR バッジは非表示）。

| ケース（具体例） | 表示されるバッジ（左 → 右の順） | 備考 |
| :--- | :--- | :--- |
| 監視リポジトリ未登録（0 リポジトリ） | `[⚪ 0リポジトリ]` | |
| Open PR が 0 件（エラーなし） | `[🟢 ✓ 0 PR]` | カード本文は「現在 Open な Pull Request はありません」 |
| Open PR が 0 件だが 1 リポジトリで取得エラー | `[🔴 ✕ 1 リポエラー]` `[⚪ 0 PR]` | エラーのあるリポジトリカードのみ本文に表示 |
| PR 2個とも CI OK | `[🟢 ✓ All Passed]` | 全件 `SUCCESS` のとき `All Passed` |
| PR 2個のうち 1個が CI OK、1個が CI 実行中 | `[🟡 ⟳ 1 Running]` `[🟢 ✓ 1 Passed]` | |
| PR 2個とも CI 実行中（完了 0 個） | `[🟡 ⟳ 2 Running]` | 0 件の `Failed` / `Passed` は非表示 |
| PR 2個のうち 1個が CI OK、1個が CI 失敗 | `[🔴 ✕ 1 Failed]` `[🟢 ✓ 1 Passed]` | |
| PR 2個のうち 1個が CI 実行中、1個が CI 失敗 | `[🟡 ⟳ 1 Running]` `[🔴 ✕ 1 Failed]` | |
| PR 2個とも CI 失敗 | `[🔴 ✕ 2 Failed]` | |
| 上記いずれか ＋ 1 リポジトリで取得エラー | `[🔴 ✕ 1 リポエラー]` ＋ 上記バッジ | 先頭（左端）に `X リポエラー` が追加される |

#### (2) 第2階層：リポジトリカードヘッダー (`RepoCard`)
※Open PR が 0 件かつエラーのないリポジトリはカード自体が非表示になります。
- **左側バッジ**: `[🔒 Private]` または `[🌐 Public]` ＋ `{totalPrs}件`（⚪ 灰）
- **右側サマリーバッジ**: 親カードと同一ルールで左から順に並記します。

| ケース（リポジトリ単位、例: PR 2個） | 表示されるバッジ（左 → 右の順） |
| :--- | :--- |
| 取得エラーにより表示され、PR は 0 件 | `[⚪ 0 PR]` |
| PR 2個とも CI OK | `[🟢 ✓ All Passed]` |
| 1個が CI 実行中、1個が CI OK | `[🟡 ⟳ 1 Running]` `[🟢 ✓ 1 Passed]` |
| 1個が CI 失敗、1個が CI OK | `[🔴 ✕ 1 Failed]` `[🟢 ✓ 1 Passed]` |
| 1個が CI 実行中、1個が CI 失敗 | `[🟡 ⟳ 1 Running]` `[🔴 ✕ 1 Failed]` |
| 2個とも CI 失敗 | `[🔴 ✕ 2 Failed]` |

#### (3) 第3階層：PR アイテム (`PullRequestCard`)
右上には Check の状態ごとに個数バッジを並記し、全 Check 成功時は `All Passed` を表示します。

| ケース（PR 単位） | 表示されるバッジ（左 → 右の順） |
| :--- | :--- |
| 全 Check が成功 | `[🟢 ✓ All Passed]` |
| 1個の Check が実行中、2個が成功 | `[🟡 ⟳ 1 Running]` `[🟢 ✓ 2 Passed]` |
| 1個の Check が失敗、2個が成功 | `[🔴 ✕ 1 Failed]` `[🟢 ✓ 2 Passed]` |
| すべての Check が失敗（例: 2個） | `[🔴 ✕ 2 Failed]` （Check詳細なし時は `[🔴 ✕ Failed]`） |
| CI 設定なし（Checks 0 個 & `overallCiState: NONE`） | `[⚪ No CI]` |

### 4.3 `Actions Status` カード（2階層）

#### (1) 最上位階層：`Actions Status` 親カードヘッダー (`ActionsStatusCard`)
- **タイトル横件数バッジ**: `{attentionRuns.length}件`（⚪ 灰：実行中＋未解決失敗の合計件数。close 済み PR に紐づく失敗は除外）
- **右側サマリーバッジ**: 条件に応じて **左から順に並記** されます（初回ロード中 `isLoading=true` の間は Running / Failed / All Passed は非表示）。

| ケース | 表示されるバッジ（左 → 右の順） | 備考 |
| :--- | :--- | :--- |
| 全ワークフローの最新実行が成功（実行中 0・失敗 0） | `[🟢 ✓ All Passed]` | タイトル横は `0件` |
| 1個が実行中、失敗 0個 | `[🟡 ⟳ 1 Running]` | タイトル横は `1件` |
| 実行中 0個、1個が未解決の失敗 | `[🔴 ✕ 1 Failed]` | タイトル横は `1件` |
| 1個が実行中、2個が未解決の失敗 | `[🟡 ⟳ 1 Running]` `[🔴 ✕ 2 Failed]` | 進行中が左、失敗が右に並記（タイトル横は `3件`） |
| API エラー / レート制限スキップ等の警告あり | `[🔴 ! 取得エラーあり]` （＋取得できた分の `Running` / `Failed`） | エラー・警告時は 0 件でも `All Passed` を出さない |

#### (2) 第2階層：ワークフロー実行アイテム
- **右上ステータスバッジ**: 実行中は `[🟡 ⟳ Running]`、失敗は `[🔴 ✕ Failed]`
- **トリガーイベントバッジ**: `release` (🟣 紫) / `pull_request` (🟢 緑) / `schedule` (🔵 水色) / `dispatch` (🟡 黄) / `push` 等 (Indigo)

### 4.4 `Actions Usage` カード（2階層）

#### (1) 最上位階層：`Actions Usage` 親カードヘッダー (`ActionsUsageCard`)
- **タイトル横件数バッジ**: `{N}アカウント`（⚪ 灰）
- **右側サマリーバッジ**:

| ケース（例: 個人＋Org の 2 アカウント監視時） | 表示されるバッジ（左 → 右の順） |
| :--- | :--- |
| 全アカウントとも「順調 (目安内)」 | `[🟢 ✓ All 目安以下]` |
| 1 アカウントが「やや速い」、1 アカウントが「順調」 | `[🟡 ⚠ 1 やや速い]` `[🟢 ✓ 1 目安以下]` |
| 1 アカウントが「超過（ハイペース/残り僅か）」、1 アカウントが「順調」 | `[🔴 ! 1 超過]` `[🟢 ✓ 1 目安以下]` |
| 2 アカウントとも「超過」 | `[🔴 ! 2 超過]` |
| いずれかのアカウントで API 取得エラー発生 | `[🔴 ! 取得エラーあり]` ＋ 上記バッジ |

#### (2) 第2階層：アカウント別カード (`AccountUsageCard`)
- **残量バッジ**: `残X,XXX分 (Y%)`（残り 200 分以上は 🟢 緑文字、残り 200 分未満は 🔴 赤枠・赤文字）
- **ペースバッジ**:
  - 使用率 ≥ 90% または 残り < 200分: `[🔴 ⚠ 残り僅か]`
  - 暦日進捗より +15pt 超: `[🔴 ⚠ ハイペース]`
  - 使用率 ≥ 85% または 暦日進捗より +5pt 超: `[🟡 ! やや速い]`
  - それ以外: `[🟢 ✓ 順調 (目安内)]`
- **取得エラー時**: `[🔴 取得エラー]`

---

### 4.5 `Self-hosted Runners` カード（2階層）

#### (1) 最上位階層：`Self-hosted Runners` 親カードヘッダー (`RunnersCard`)
- **タイトル横件数バッジ**: `{N}台`（⚪ 灰）
- **右側サマリーバッジ**:

| ケース（例: 3台登録時） | 表示されるバッジ（左 → 右の順） | 備考 |
| :--- | :--- | :--- |
| ランナー未登録（0台・エラーなし） | `[⚪ 0台]` | |
| 3台とも Online（すべて待機中） | `[🟢 ✓ All Online]` | |
| 3台とも Online（うち 1台がジョブ実行中） | `[🟡 ⟳ 1台 Running]` `[🟢 ✓ All Online]` | 実行中台数が左に並記され、全台 Online のため `All Online` |
| 2台 Online（うち 1台実行中）、1台 Offline | `[🟡 ⟳ 1台 Running]` `[🔴 ✕ 1台 Offline]` `[🟢 ✓ 2台 Online]` | 各状態の台数が色別に並記 |
| 3台とも Offline | `[🔴 ✕ 3台 Offline]` | |
| Org 権限不足等の警告・エラーあり | `[🔴 ! 取得エラーあり]` ＋ 上記バッジ | 先頭に `取得エラーあり` を追加 |

#### (2) 第2階層：個別ランナーカード (`RunnerCard`)
- **ステータスバッジ（1つのみ排他表示）**:
  - `busy === true`: `[🔵 Busy (実行中)]`（水色・点滅ドット）
  - `status === 'online'`: `[🟢 Online]`（緑ドット）
  - `status === 'offline'`: `[🔴 Offline]`（赤ドット）
