# テスト方針 & テスト観点仕様書 (`docs/dev/testing.md`)

本ドキュメントは、Personal Dev Dashboard における自動テストの全体像、テスト観点、検証項目、および開発者がテストを追加・保守するためのガイドラインをまとめたものです。

---

## 1. テスト戦略と基本方針

本アプリケーションは **完全クライアント完結型 (Zero-Backend SPA)** であり、バックエンドサーバーが存在しません。そのため、以下の 2 つを最優先の品質目標としてテストを設計しています。

1. **🔒 セキュリティ & プライバシーの絶対的保証**:
   - ユーザーがブラウザ内に入力・保存した GitHub Personal Access Token (PAT) が、外部のサーバーや第三者に漏洩しないことをテストコードで自動検証・証明します。
2. **🧮 ロジックの正確性とリグレッション防止**:
   - Actions 無料枠の消費ペース判定、月末日数計算（うるう年対応など）、localStorage 設定の永続化、および主要 UI コンポーネントの表示崩れを防ぎます。

---

## 2. テスト環境・技術スタック

| ツール | 用途 | 選定理由 |
| :--- | :--- | :--- |
| **Vitest** | テストランナー & アサーション | Vite と完全統合されており、設定レスで超高速（ローカル実行で約 2〜3 秒） |
| **React Testing Library** | React コンポーネントテスト | 実装詳細ではなくユーザー視点での DOM 振る舞いを検証可能 |
| **@testing-library/jest-dom** | DOM マッチャー拡張 | `toBeInTheDocument()`, `toHaveClass()` 等の直感的なアサーション |
| **jsdom** | ブラウザ環境シミュレーション | Node.js 上で DOM, `window`, `localStorage`, `fetch` をエミュレート |

## 3. テスト観点・項目一覧

### 3.1 🔒 PAT セキュリティ & 非漏洩テスト (`src/services/security.test.ts`)
Personal Access Token (PAT) が安全に取り扱われ、設計通りの局所性（ローカル完結）が保たれているかを検証します。

| No | テスト項目 | 検証観点 | 保証されること |
| :---: | :--- | :--- | :--- |
| 1 | **通信先ホワイトリスト検証** | アプリが発行する全 HTTP リクエスト（`fetch`）の宛先 URL ホスト名を監視 | 外部プロキシ、怪しい解析サーバー、サードパーティ API への通信が一切発生せず、**公式の `https://api.github.com/` のみと通信** していること |
| 2 | **ヘッダー局所性検証** | トークンの送信形態を検証 | URL パスやクエリパラメータに PAT が露出せず、**HTTPS かつ `Authorization: Bearer <token>` ヘッダーでのみ送信** されていること（ブラウザ履歴やアクセスログへの残存防止） |
| 3 | **保存先局所性検証** | トークン保存処理（`saveSettings`）実行後のブラウザ内ストレージを検証 | `localStorage` の特定設定キー（`personal_dev_dashboard_settings`）以外、すなわち **Cookie や `sessionStorage` などに PAT が書き込まれない** こと |
| 4 | **コンソールログ漏洩防止検証** | 通常実行時および API エラー時（401 Unauthorized 等）のコンソール出力を監視 | `console.log`, `console.warn`, `console.error` に **生の PAT 文字列が出力されない** こと |

---

### 3.2 🧮 Actions 使用量・ペース判定ロジック (`src/utils/actionsUsage.test.ts`)
GitHub Actions 無料枠の利用状況・ペース判定に関する計算の正確性を検証します。

| No | テスト項目 | 検証観点 | 期待値・ルール |
| :---: | :--- | :--- | :--- |
| 1 | **小の月（30日）の日数計算** | 4月, 6月, 9月, 11月の日数 | 30 日と判定されること |
| 2 | **大の月（31日）の日数計算** | 1月, 3月, 5月, 7月, 8月, 10月, 12月の日数 | 31 日と判定されること |
| 3 | **うるう年と平年の2月計算** | 2024年（うるう年）と 2025年（平年）の日数 | 2024年は 29 日、2025年は 28 日と判定されること |
| 4 | **上限近接ペース判定** | 使用率が 90% 以上の場合 | ステータスが `残り僅か`、警告グラデーション（赤）になること |
| 5 | **ハイペース判定** | 当日の暦日目安比 +15% 超過 かつ 使用量 >= 100分 | ステータスが `ハイペース`、警告グラデーション（赤）になること |
| 6 | **やや速いペース判定** | 当日の暦日目安比 +5% 超過 かつ 使用量 >= 100分 | ステータスが `やや速い`、注意グラデーション（黄）になること |
| 7 | **平準・順調ペース判定** | 上記の超過条件に該当しない場合 | ステータスが `順調 (目安内)`、安心グラデーション（緑）になること |
| 8 | **負数防止ガード** | 使用量がクォータ枠（2,000分）を超過した場合 | 残り分数がマイナスにならず `0 分` でクランプされること |

### 3.3 💾 設定管理 & ストレージ (`src/services/storage.test.ts`)
ブラウザ `localStorage` を用いた設定（PAT、監視リポジトリ一覧、更新間隔等）の永続化を検証します。

| No | テスト項目 | 検証観点 | 期待値 |
| :---: | :--- | :--- | :--- |
| 1 | **未保存時のデフォルト値取得** | `localStorage` に何も保存されていない初回起動時 | 安全なデフォルト設定（空の PAT、リフレッシュ 60 秒など）が返ること |
| 2 | **保存と読み出しの整合性** | `saveSettings` で保存したカスタム設定 | `loadSettings` で型を維持したまま欠損なく復元できること |
| 3 | **不正 JSON への耐障害性** | `localStorage` の値が手動編集等で壊れた JSON だった場合 | アプリがクラッシュせず、エラーログを吐いて安全にデフォルト値へフォールバックすること |
| 4 | **設定クリア（ログアウト）** | `clearSettings` を呼び出した場合 | `localStorage` からキーが削除され、PAT が初期化されること |

---

### 3.4 🖥️ UI コンポーネント描画 (`src/components/ActionsUsageCard.test.tsx`)
今回整理した Actions 使用量カードのレンダリング挙動を検証します。

| No | テスト項目 | 検証観点 | 期待値 |
| :---: | :--- | :--- | :--- |
| 1 | **ローディング表示** | `isLoading = true` かつデータ未取得時 | スケルトン（`animate-pulse`）が表示されること |
| 2 | **エラー表示** | `error` 文字列が存在する場合 | 警告アイコンとともにエラーメッセージが表示されること |
| 3 | **空状態（非表示）** | `usage = null` かつ非ローディング時 | 何も描画されない（DOM が空）こと |
| 4 | **正常データ描画** | 通常の使用量データが渡された場合 | 「当月の使用量」「残り無料枠」「本日目安」「OS別内訳」が欠損なく描画されること |
| 5 | **残枠逼迫時の警告色切り替え** | 残り枠が 200 分未満になった場合 | 残り枠の文字色が警告色（`text-rose-400`）へ動的に切り替わること |

## 4. テスト実行方法

### ローカルでの実行
```bash
# 全テストを 1 回実行（CI モード）
npm test

# ファイル変更を監視してテストを自動再実行（開発モード）
npm run test:watch
```

### CI (GitHub Actions) での自動実行
Pull Request 作成時および `main` ブランチへの push 時に、[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) 内で自動的に `npm test` が実行されます。すべてのテストが通過しない限りマージできません。
