# テスト・ドキュメント整合性 レビューチェックリスト

`local-review` スキルの **Stage 2（プロジェクト固有ベースライン照合）** で確認する単体テスト（Vitest / Testing Library）およびドキュメントのチェック項目です。
本リストは最低限のベースラインであり、レビュー範囲の上限ではありません（Stage 1 の自由推論を先に実施してください）。
CodeRabbit 等でテスト設計やドキュメント規約に関する新たな指摘を受けた際は、既存項目への統合を優先しつつ本ファイルに還元してください。

---

## 1. 単体テストの完全性・網羅性とアサーション強度

- [ ] **既存テストの不当な書き換え・アサーション弱体化の禁止（最重要・[`.agents/rules/testing-integrity.md`](../../../rules/testing-integrity.md) 参照）**:
  - `*.test.ts` / `*.test.tsx` の差分（`-` 行）において、本体コードの修正を通すためだけに既存の `expect(...)` を削除・緩和したり、モックデータを都合よく書き換えたりしていないか。
  - 既存のテストケースが変更されている場合、それが「ユーザーから依頼された仕様変更そのもの」に直接対応する正当な変更か（本体コードのデグレを隠蔽する変更になっていないか）。正当な理由なき既存テストの弱体化は **🔴 Critical** として差し戻すこと。
- [ ] **テスト間のキャッシュ・モジュール状態汚染の防止**:
  - `githubApi.ts` 等にモジュールスコープのキャッシュがある場合、テストの `beforeEach` でキャッシュクリア関数（`clearWorkflowRunsCache()` 等）を呼び出し、テスト順序に依存しない独立性を保っているか。
- [ ] **UI テストの具体的なアサーション**:
  - ヘッダーのサマリーバッジ（`1 リポエラー` 等）だけでなく、その条件で実際に表示されるべきカード名・エラー本文・空状態メッセージまで `expect(...).toBeInTheDocument()` で検証しているか。
  - 「再実行で成功したら消える」などの状態変化テストでは、初期描画だけでなく `rerender` による同一 ID 更新ケースも検証しているか。
  - DOM 要素のテキスト変更（例: `octocat/repo` → `Repo: octocat/repo`）を行った際、既存の統合テスト（`App.test.tsx` 等）でテキスト重複や未検出が発生しないか。
- [ ] **設定マイグレーション・後方互換テスト (`src/services/storage.test.ts`)**:
  - 新しい Feature ID や設定項目を追加した際、既存の `localStorage` 保存データ（新キーが存在しない JSON）を読み込んだときにデフォルト値で安全に補完され、既存の他設定が維持されるテストを追加したか。
- [ ] **セキュリティテスト (`src/services/security.test.ts`)**:
  - 新しい API 通信関数を追加した際、`security.test.ts` の「通信先ホスト検証」と「Authorization ヘッダー検証」の**両方**のテストケースにその関数の呼び出しを追加したか。

## 2. ドキュメント・Docstring・Markdown 品質

- [ ] **JSDoc / Docstring カバレッジ（CodeRabbit Pre-merge Check 80% 基準）**:
  - 変更・新規作成した `.ts` / `.tsx` ファイル内のエクスポート関数・React コンポーネント・主要な内部ヘルパー関数に JSDoc（`/** ... */`）が付与されているか。
- [ ] **Markdownlint ルール（`MD022` / `MD031` / `MD032`）の遵守**:
  - 変更・新規作成した `.md` ファイルにおいて、見出し（`#`〜`####`）の前後、フェンス付きコードブロック（```` ``` ````）の前後、および箇条書きリストの前後に必ず空行（blank line）が入っているか。
- [ ] **実装仕様とドキュメント説明の一致**:
  - `README.md`、`docs/dev/ui-design.md`、`docs/dev/api-design.md` に記載した表示条件（例: 「0件かつエラーのないリポジトリは非表示」）、エンドポイント引数（例: `per_page=30`）、デバッグバー対象カード一覧が実装と完全に一致しているか。
- [ ] **見出し番号やリンクの整合性**:
  - Markdown ドキュメントにセクションを追加・挿入した際、後続のセクション番号（`### 3.4`, `### 3.5` 等）の重複やズレが発生していないか。
